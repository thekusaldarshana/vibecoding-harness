# Maintain verification

Compare the feature map and commands with current code, recent diffs, and
reported verification failures. Prioritize changed journeys, broken
selectors, auth/setup drift, and recurring blind spots. Run the affected
commands before updating documentation so the map describes observations.

Repair controls, update feature pages and their verified revision, and add
focused regression checks for demonstrated failures. Preserve assertions
unless the intended behavior changed. Remove obsolete claims rather than
leaving contradictory instructions. Document untestable account states.

Schedule maintenance with the user's existing automation only if requested;
this workflow installs no daemon or vendor-specific daily cloud job. Use it
on demand and after changes to navigation, state, setup, or control surfaces.
