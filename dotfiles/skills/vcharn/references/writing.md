# Technical writing

Choose the document's purpose before drafting: a tutorial teaches by doing,
a how-to solves an experienced reader's task, reference specifies an
interface, and explanation develops the reasons and tradeoffs. Separate
these when mixing them would obscure the reader's goal.

For a new API, start with a caller's usage example and verify it against an
implementation or prototype. State prerequisites and expected output. Keep
claims proportional to evidence and mark incomplete behavior honestly.
Write plain sentences, concrete examples, and source links where useful.
Remove repetition, promotional claims, invented terminology, and jargon
that adds no precision. For a repository README, use readme-craft if
available; its bundled checker validates local links and anchors offline.
